# Manual multi-bottle mL recipes

User requirement: retain a multi-bottle entry in Equipment & Calibration; enter bottle and each source's mL only. Keep existing single-bottle entry and formal mass experiment pages.

Design: a five-row table (bottle selector, source10..15 volumes), all-zero rows skipped, duplicate selected bottles rejected. No project or g/step requirement. Reuse `_recipe_plan` exactly: PEG correction/source calibration, logical bottle routing, one aspiration/chase per source, per-bottle mix and water rinse toward waste. Preview optional and nonmoving. Validate every selected bottle before the first physical motion.

Backend task: add ManualBatchMixin (`manual_batch.py`) to Controller, action `batch_recipe`, preview `/api/batch-recipe-preview`, state `manual_batch_run`. Payload `{recipes:[{sample,items:[{source,volume_ml}]}],mixing?,request_id}`. Plans use `recipes` containing frozen single-bottle plans. One worker owns the full batch. Reset manual disturbance notification for each actually reached bottle, using its logical sample id; untouched bottles remain undisturbed. Stop or fault cancels later recipes and preserves completed actions; no restart resume. Persist batch request/outcome under data/manual_batches and deduplicate request_id; reusing an ID with changed inputs rejects before motion.

UI task (delegated): index card + `manual-batch.js` and small console hooks. Expose `window.ATPSManualBatch({api,action,bind,notice,getState})` -> `{render(state)}`. Optional preview and start buttons, per-bottle progress/status, no browser-side action loop. User enters only bottle and mL. Send global existing single-bottle mixing fields; show source meanings and bottle-to-port labels. Retain request ID for ambiguous HTTP failures, generate new for explicit subsequent runs. Narrow-width table scroll confined to card. Refresh never starts movement. Keep common-tube residual-water caveat brief.

Tests: full prevalidation/no partial dose; physical mapping and source order; once-per-bottle mix/rinse/no16purge; per-bottle disturbance; stop preserves connection and skips later bottles; idempotent retry after completion/restart; invalid/different id request rejected; optional offline preview. Browser test against real production controller with fake hardware, including stopped batch, input edits, no project requirement and reload without action. Full regressions before commit/sync. Update existing running service only idle and restore connection; never dose real hardware as a test.
