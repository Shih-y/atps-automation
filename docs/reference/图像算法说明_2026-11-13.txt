图像识别与光学分相候选算法说明（2026-11-13）

适用范围
程序在浏览器本地对已获取的未镜像 RGBA 图像执行确定性的图像启发式分析，
不调用云端视觉模型，不包含训练后的深度学习模型，不会自行启动相机或操作泵阀。
相机是否打开、原图与结果是否归档由操作页面单独控制。
本版尚未使用本实验体系的真实图像完成验证，不提供准确率、检出限或重复性承诺。

瓶体识别与编号
1. 为限制运算量，自动定位将图像等间隔采样到不超过 640×480 的工作网格。
2. 寻找连续的竖向亮度边缘，竖边至少跨越画面高度的 35%。
3. 相邻竖边只有在顶部、底部有横向闭合支持，且宽高比、尺寸合理时，才组成瓶体候选。
4. 只有恰好五个且尺寸、垂直排列一致的候选，才按画面由右至左分配瓶号 1、2、3、4、5。
5. 空白、随机噪声、一个瓶子或缺少瓶子的画面不会被强行均分成五个框。
   未确定五瓶时返回空 rois、空 bottles、候选数量和原因，请人工框选。

这是形状候选识别，不能证明候选物一定是玻璃瓶。背景中的矩形、标签、支架也可能干扰。
瓶肩弯曲、瓶体透明得难以分辨、遮挡、倾斜、尺寸不一、镜头距离不合适时可能漏检。
自动识别成功后仍应核对框的位置和右到左瓶号；拍摄必须保持未镜像。

手动框选
可输入 1–5 个瓶体的 {sample,x,y,width,height}，坐标单位为原图整数像素。
sample 必须为 1–5 中不重复的整数，填写实际瓶号，允许只提交如 1、3 号的子集。
已提交瓶体的中心位置须按瓶号从小到大由右向左排列；框不能重叠或越出原图。
每框至少 20×40 像素，应包含完整直立瓶体，而非任意裁取的一小块液体。
只提交部分瓶体时返回 detection.status="partial"，missing_samples 列出未指定的瓶号，
rois 和 bottles 仅包含实际提交的瓶体；缺失瓶体不自动补框、不重新编号，也不推断分相结果。
这允许分别分析和归档已经明确框选的瓶体，不影响自动模式必须识别五个一致候选的要求。
传入不合法的手动框后不会悄悄改用自动定位，而是返回 detection.status="invalid"。
手动空数组仍视为无效输入；自动模式空画面则保持 uncertain，可单独保存原始照片。
几何有效不代表图像有效：空白照片即使框选了五个矩形，分相结果也保持 uncertain。

液体区域与候选界面
仅检查瓶框横向 20%–80%、纵向 25%–85% 的内部区域，减少瓶壁、瓶盖、常见顶端液面、瓶底干扰。
内部横向分成五条竖带，逐行计算 RGB 均值。
比较候选位置上下的窄带颜色，并检查更远上下窄带能否维持相近颜色平台。
界面需要至少四条竖带共同支持、变化方向相符、颜色差达到阈值，且局部变化足够集中。
薄的单条暗线、弥散照明渐变与持续颜色台阶不同；多个分离候选界面会保留不确定。
所有位置均以原图像素坐标返回；interface_y 是横向候选界面的纵坐标。

质量与稳定性
以下问题使该瓶保持 uncertain：
- 像素缺失或透明；过曝反光比例偏高；明显曝光不足。
- 光学对比度低，或瓶边不够清晰。
- 较多局部不均匀纹理（可能是气泡、污点、标签或其他干扰，算法不能确诊气泡）。
- 微弱/弥散颜色变化，或多个界面候选。
- 与提供的上一帧相比，瓶框变化、颜色区域变化、界面高度变化或候选类别变化较大。
- 已传入上一帧但对应瓶的图像摘要/几何信息不足，无法进行比较。

代表性起始阈值：竖边亮度差 14；界面 RGB 平均绝对差 8；微弱变化阈值 3；
内部近白像素比例超过 3% 视为反光；局部纹理比例超过 12% 视为干扰；
瓶边清晰度小于 10 视为模糊或弱边缘；界面位移超过瓶高 6% 视为不稳定。
这些值是工程启发式起点，未通过本实验数据标定。完整算法由 method 版本和代码确定，
主要设置随结果的 settings 一起返回，便于与原图、框选一起归档和复查。

如需帧间检查，应将上次完整分析结果以 options.previous 传回。
未提供上一帧时 quality.stability="not_checked"，不能据此声称样品已经静置稳定。
有可比较上一帧时返回 stable 或 unstable；缺少可比较信息时返回 unavailable。
此检查不计量时间、不验证等待时长，也不能发现两次快照之间的全部运动。

结果含义
single：所检查区域没有检出明显光学界面，仅为“光学单相候选”。
two_phase：检测到满足上述条件的持续横向颜色界面，仅为“光学分相候选”。
uncertain：定位/质量/界面/稳定性证据不足，不能给出上述候选。
single 不证明热力学单相，two_phase 不证明已达平衡，也不代表组成、相体积或浓度测定。
低对比真实界面可能看不见；可见分界也可能来自照明、反射、贴纸、液面或沉淀。
固定内部裁剪无法保证去除任何高度的液面，界面落在排除区时可能漏检。
以上质量门限只能筛掉部分异常，不保证发现所有模糊、气泡或反光。
无法可靠判断时请人工复核原图，单独记录人工标签，不要覆盖算法候选。

程序接口
浏览器：PhaseAnalysis.analyzeFrame(imageData, {rois?, previous?})
Node：require('../static/phase_analysis.js').analyzeFrame(...)
imageData 为 {width,height,data}，data 为按行排列的 RGBA Uint8ClampedArray。
有效图像最小 80×60、最大 2400 万像素；不透明像素应占至少 99%。
结果：
{
  rois: [{sample,x,y,width,height}],
  bottles: [{sample,classification,reason,interface_y,candidate_interface_y,
             inspected_region,quality:{flags,stability,signature,...}}],
  detection: {status,source,candidate_count,missing_samples?,reason},
  method: "local-optical-heuristic-v1",
  validated: false,
  settings: {...},
  limitation: "..."
}
detection.status 为 ok / partial / uncertain / invalid；source 为 auto / manual。
status=ok 只说明取得五个可用几何框；partial 说明手动指定了 1–4 个合法瓶框。
两种状态下瓶子的 classification 仍可能全部为 uncertain。
成功接受框选后 missing_samples 为未指定瓶号列表（完整五瓶时为空数组）；
自动检测未确定五瓶或输入无效时不填写该字段，避免推断具体缺失哪个瓶号。
uncertain 时 interface_y 为 null；candidate_interface_y 保留被质量门限否决的候选位置供复查。
quality.signature 是内部颜色摘要，用于下一帧比较，不是置信度，也不替代原始照片。
结果可 JSON 序列化，函数不修改传入的原始像素或手动框。

软件检查与真实验证的区别
program/tests/phase_analysis.test.js 使用人工生成的 RGBA 图案检查：
空白、噪声、五瓶定位、缺瓶、右到左编号、人工框校验与部分瓶号子集、持续界面、弱对比、
反光、气泡样纹理、模糊、瓶盖/瓶底排除、薄线与照明渐变、框外干扰、
帧间变化、上一帧缺失信息、JSON 与浏览器无相机/网络调用。
运行：在仓库目录执行 node --test program/tests/phase_analysis.test.js。
这些测试仅验证软件行为，不能替代真实实验准确率评估。
后续应采集覆盖不同液位、配方、光照、浑浊度、气泡和静置时间的原始照片，
由实验人员独立标注，并在未用于调阈值的图像上报告漏检、误检和 uncertain 比例。
